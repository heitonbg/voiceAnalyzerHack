# PrivateScribe

Android 10+, Kotlin / Compose / Material 3. Полностью локальная запись, русская транскрибация,
глобальная диаризация, JSON и выбор важных цитат локальной Qwen3.

## APK со всеми моделями

Готовый APK: **app/build/outputs/apk/debug/app-debug.apk**.
В нём уже находятся GigaAM v3 RNNT INT8, Silero VAD, Pyannote segmentation 3.0,
TitaNet Small и Qwen3-0.6B Q8_0. Никаких папок моделей и скачивания на телефоне.
Первый запуск копирует полный набор из 12 файлов моделей в приватное хранилище и проверяет SHA-256.
Основной GigaAM v3 E2E RNNT INT8 encoder занимает 224,571,327 bytes (decoder/joiner/tokens идут отдельно). Точный размер финального APK в этой итерации не замерен.
Свободное место: заложите не менее 2.5 GB на установку, распакованные веса и аудио.
APK содержит arm64-v8a и x86_64. INTERNET в manifest отсутствует; backup отключён.

Установка: Android Studio Run либо adb install -r APK. Дождитесь подготовки моделей в настройках.
Выберите «Загрузить аудио»: запись открывается и обработка запускается автоматически.
Для диктофона откройте сохранённую запись и нажмите «Распознать речь».
После COMPLETE доступны JSON, исправления текста/говорящих, имена участников и ИИ-анализ.
Смена числа участников в настройках применяется к следующему проходу; повтор создаёт новую копию.

## Реализовано

- AudioRecord mono 16 kHz, pause/resume/stop, реальный RMS, foreground service.
  Аудио пишется независимо от ML; распознавание запускается после записи.
- SAF импорт без широких storage permissions, приватная копия оригинала.
- Блочный MediaExtractor/MediaCodec decoder, mono / sinc-resampling 16 kHz на диск.
- Основной пайплайн: параллельное декодирование на диск → Pyannote/TitaNet по окнам до 32 s
  → глобальные voice embeddings → GigaAM один раз на фразу. Реплики поступают в Room сразу.
  Говорящие предварительные до завершения глобальной кластеризации. Silero работает в ASR-only
  резервном пути; основной путь использует non-speech классы Pyannote, чтобы не каскадно терять тихую речь.
- ASR запускается по мере поступления декодированного PCM; готовые фразы сохраняются и появляются
  до завершения полного файла. Временные границы речи берутся из Pyannote, слова — из emission
  timestamps RNNT, когда выход native token timing проходит проверку. Это приблизительные оценки,
  не forced alignment; точность границ по независимой временной разметке не измерена.
- Одиночным коротким голосовым выбросам недостаточно свидетельств для нового speaker_id.
  В карточке результата доступны 3 / 4 / 5 участников для уточнения известного числа людей.
- Прогрессивные реплики, фактическое положение в аудио, отмена, checkpoints,
  продолжение после прерывания. Короткие спорные голосовые фрагменты сверяются с обоими
  соседями; overlaps и недостаточно подтверждённые голоса остаются speaker_unknown.
  После основного прохода идёт последовательная проверка аудио с конца; она может заполнить
  только неизвестные IDs, сохраняя уверенные метки первого прохода. Это добавляет время
  обработки и пока не прошло end-to-end на обновлённом APK.
- В расшифровке есть поиск и фильтр по участникам. Автопрокрутка новых реплик выключена
  по умолчанию; пользователь может перейти к новым репликам или включить слежение.
  Воспроизведение по временной метке, правка с сохранением raw ASR, переименование.
- Строгий JSON: только transcript и speaker_id/start_ms/end_ms/text.
- JNI llama.cpp CPU, Qwen3: анализ по категориям и Q&A с проверяемыми ID реплик.
  Вопрос к Qwen открывается в отдельном диалоге; ответ показывает найденные исходные цитаты
  как ссылки к соответствующему аудио. Анализ экстрактивный: вымышленные пересказы не выдаются
  за факты. Chunking и иерархический отбор ограничивают контекст 2048 токенами.
- ASR и диаризация остаются загруженными между окнами; их вычисления последовательны.
  Декодирование выполняется параллельно с ограниченными PCM-буферами и файлом на диске.
  LLM использует общую блокировку и не загружается вместе с ASR/диаризацией; native release в finally.
  Анализ и транскрибация используют foreground services, запись — отдельный service.
- Светлая/тёмная/системная темы, Dynamic Color, системные insets, масштабируемый текст,
  ленивые списки, состояния подготовки/ошибки/отмены.

Исправлена проверка несовместимых одновременно активных дорожек при окончательном выборе глобального ID. Синтетическая регрессия и Android smoke прошли; влияние на метрику эталонной встречи пока не измерено.

## Фактическая проверка

Android Emulator API 36 / native x86_64 / 4096 MB:

- JVM unit suite прошёл; проверяет WAV recovery, sinc-resampling, chunk planning, native word timing, speaker assignment и слияние фраз.
- Реальные Android tests записи/паузы и импорта; VAD, русский RNNT, Pyannote/TitaNet.
- Четыре голоса на публичном китайском fixture: глобальное сопоставление между окнами
  с заданным числом 4, восстановление checkpoint.
- Русский end-to-end из **моделей в APK**, финальная диаризация, строгие JSON-ключи,
  сохранение raw ASR при правке, настоящий JNI Qwen анализ и вопрос про дерево.
  Успешный прогон BundledOfflineTest: 15.879 s; анализ 6176 ms, вопрос 4691 ms.
- Нагрузочный LongAudioTest: 80 повторений настоящего публичного русского WAV,
  903200 ms аудио → 192010 ms обработки, RTF 0.21259, 81 финальная реплика.
  Это **stress**, не независимый 15-минутный разговор и не WER/DER.
- Полные проходы одной реальной 21:53 записи: v6 — 79,805 ms / 1,908 ms до первой
  реплики / 75 unknown из 268; v7 с консервативной обработкой коротких соседних overlaps —
  79,878 ms / 3,362 ms до первой реплики / 63 unknown из 268. В обоих результатах 3 кластера.
  Переключение версии архивирует прежние финальные строки и запускает единый свежий проход.
  Предыдущая кластеризация давала 9 голосов. На этой записи число unknown уменьшилось,
  но 63 неизвестных сегмента остаются проблемой. Нет эталонных меток: это не DER и не
  подтверждение правильности каждого speaker_id.
- Последняя настройка v19 склеивает соседние слова одного говорящего через паузы до 1.5 s,
  увеличивает верхнюю границу реплики до 90 s и соединяет знаки препинания без пробела.
  На свежем прогоне 21:53 аудио число строк снизилось с 277 до 241, при этом WER остался
  14.31% (405 правок / 2,830 слов). Реплика появилась через 5.93 s; вычислительный этап
  занял 267.3 s (RTF 0.204, примерно 4.9× быстрее реального времени) на API 36 x86_64 / 4 GB.
  Это сокращает излишнюю фрагментацию, но не ускоряет сам инференс и само по себе не
  доказывает правильность границ реплик. Из 2,532 точно выровненных слов знак после слова
  совпал с эталоном в 93.92% случаев; этот показатель исключает ошибочно распознанные слова
  и не является точностью интонации. 4 ID заданы для прогона, 80 строк остались unknown;
  speaker-onset match 36.22%, средняя ошибка ближайшего старта 4.83 s. Диаризация и точность
  временных границ остаются неудовлетворительными. sampled PSS — 813,504 KiB. Подробный
  агрегат: [v19 без текста](docs/results/reference-evaluation-titanet-v19.json).
- Двунаправленный кандидат отклонён: обратный Pyannote/TitaNet прогон добавил 146.1 s;
  наивное объединение снизило onset match до 35.43%, а заполнение unknown показало 42.52%
  только на 127 началах одного эталона. Выигрыш не подтверждён независимо, поэтому полный
  повторный проход в production не используется. [Сводка](docs/results/reference-evaluation-bidirectional.json).
- Android CPU thread sweep на публичных WAV показал лучший результат из проверенных при
  4 потоках: GigaAM 11.29 s за 0.688 s (RTF 0.061); Pyannote/TitaNet 56.86 s за 3.519 s
  (RTF 0.062). На четырёхголосом fixture diarizer выдал 8 кластеров при всех потоках —
  пере-кластеризация осталась реальной проблемой. Это модельный smoke без WER/DER и не
  основание переносить 4 потока на ARM. [Профиль](docs/results/cpu-thread-profile.json).
- Полный прогон v22 с автоматическим числом участников: WER 14.31%, speaker-onset
  36.22%, 86 unknown из 238 строк, RTF 0.2035. В v25 учёт overlap на границах слов
  сократил unknown до 82 из 235 строк при тех же WER 14.31% и onset 36.22%;
  время 263.711 s, RTF 0.2008. Это улучшение покрытия, не доказанный рост точности
  speaker_id. Аудит сохранённых Android checkpoint на 127 эталонных началах показал
  63 расхождения уже на глобальном голосовом интервале и 6 после привязки слов.
  Категории диагностические из-за грубых эталонных timestamp; проверенного улучшения
  кластеризации пока нет. [CSV](docs/results/reference-stage-audit.csv),
  [сводка](docs/results/reference-stage-audit-summary.json).
  Четыре CPU-потока замедлили полный прогон, поэтому production использует
  2 потока ASR и 1 поток диаризации. Replay на cached embeddings сравнил четыре
  auto-порога и K=4 через настоящий planner/merger; выигравшей конфигурации нет.
  [Замеры](docs/testing.md), [исследование методов](docs/DIARIZATION_RESEARCH.md).
- Приоритетный полнофайловый Android-эксперимент проверил один вызов sherpa-onnx
  на всей записи с теми же сохранёнными ASR-словами. Auto создал 85 native ID и дал
  13/127 speaker-onset; K=4 дал 47/127 против 46/127 у v25, но только отдельная
  диаризация заняла 183.9 s. Пиковый sampled PSS: 1,372,903 KiB (auto) и 714,576 KiB
  (K=4), без ASR в памяти. Подтверждённого выигрыша нет; production остаётся v25.
  [Методика и полная таблица A/B/C](docs/WHOLE_FILE_DIARIZATION_EXPERIMENT.md).

## Ограничения

- Физический Redmi Note 9 Pro / Android 10 и ARM-inference не проверены: устройство не подключено.
  ARM-библиотека собрана, это не устройствоный тест.
- WER и speaker-onset измерены только на одной эталонной записи. v22 и полный
  четырёхпоточный кандидат установлены и проверены на x86_64 эмуляторе; текущая APK
  снова содержит проверенную конфигурацию 2/1 потоков. DER, JER, длительность unknown,
  независимая точность границ и ARM64 runtime не измерены. На публичном fixture
  diarizer выдаёт 8 IDs без эталонной разметки; качество остаётся недостаточным.
- Эталонный sampled peak PSS v19 — 813,504 KiB (200 ms sampling). Новые thread-sweep
  PSS — snapshots после отдельных model runs, не peak и не совместно загруженные модели:
  GigaAM 386–394 MiB, diarization 318–319 MiB. Это не leak check и не Redmi Note 9 Pro.
- Экспериментальный WeSpeaker ResNet34-LM прошёл x86_64 CPU inference, но был медленнее
  (474 s против 268 s у TitaNet), не восстановил 4 голоса и не улучшил надёжность временной
  привязки; поэтому он исключён из основного APK. Сводки сравнения лежат в
  `docs/results/reference-evaluation-titanet.json` и `docs/results/reference-evaluation-wespeaker.json`.
- Overlap-кандидаты построены по локальной маркировке сегментации и глобальным ID; их
  корректность отдельно не измерена. Тексты независимых одновременно говорящих не разделяются
  на отдельные ASR-дорожки. Последний прогон не подтверждает требуемую точность.
  Времена — оценённые интервалы речи, не точные границы слов.
- Живой ASR во время записи не включён. После остановки запись доступна для обработки.
- WAV проверен; MP3/M4A кодек-путь реализован, отдельная матрица форматов ещё не пройдена.
- Анализ выбирает исходные цитаты; отдельный свободный абстрактивный отчёт и автоматическая
  структуризация «ответственный/дата» не объявляются реализованными.
- Отмена ожидает завершения текущего ограниченного native-вызова. Сегменты/checkpoints
  возобновляются, LLM-анализ после process death нужно запустить заново.
- Лицензионная карточка TitaNet указывает NeMo Toolkit license; точный NOTICE экспорта
  перед публичной дистрибуцией нужно дополнительно сверить.
