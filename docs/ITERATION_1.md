# Итерация 1 — фактический результат

Дата: 2026-11-06. Это исследование Android CPU inference, не готовое приложение хакатона.

## Выполнено

- Исходный Compose-шаблон исследован; git-репозиторий изначально отсутствовал.
- Исправлены несовместимые AndroidX/SDK зависимости: исходные core 1.19 / lifecycle 2.11
  требовали SDK 37, а проект использовал compileSdk 36 / AGP 9.0.1.
- Рабочий JBR найден в Android Studio1; системный JAVA_HOME был неверным.
- sherpa 2.0.1 AAR загружен, официальный SHA256 совпал; обе нужные ABI присутствуют.
- AVD Medium_Phone запущен с -memory 4096; Android API 36, нативный процесс x86_64.
- Реальный Silero + GigaAM v3 RNNT INT8 + Pyannote FP32 + TitaNet Small inference.
- Четыре инструментальных теста прошли: OK (4 tests), последний прогон 52.082 s.
- Реальный JSON расшифровки сохранён: results/real-transcript.json.
- llama.cpp v0.9.0 commit cd959bae99ff4bed22bef2604f45241c09bbb8c8 собран NDK 27.1 для Android x86_64.
- Qwen3 0.6B Q8_0 выполнил CPU inference на Android над фактическим текстом ASR.
  Это отдельный Android executable, не интеграция JNI в пользовательское приложение.
- Исправлен Gradle Sync после ошибки Provider в старом SourceSet API:
  генерируемые тестовые assets подключены через Variant API / DirectoryProperty.
  Sync и assembleDebug / testDebugUnitTest / assembleDebugAndroidTest прошли.

Сырые отчёты лежат в results. PSS в речевых smoke JSON — **снимки**, не пики.
У llama internal performance counters были выключены: строки с inf tokens/s некорректны;
использовать wall clock счётчики собственного стенда.
Размер metadata context в загруженном GGUF: 40960, стенд ограничивает контекст 2048.
Это не заявление о пригодности всего тренировочного контекста для смартфона.

## Найденные проблемы

1. Автоматическое количество голосов чувствительно к threshold.
   0.8–0.9 подходит одному публичному китайскому примеру; перенос на русскую речь не проверен.
   Отдельный smoke с условием >=2 подтверждает запуск, а не правильное количество или DER.
2. Summary Qwen слабый: повторяет вводные метаданные вместо содержательного анализа стихотворения.
   На этом входе не выдумал решения/задачи/сроки; это не полноценная оценка grounded summarization.
3. Kotlin API offline diarization принимает полный FloatArray — для production streaming нужна другая orchestration.
4. Gradle Test Platform удаляет установленные тестом файлы после прогона.
   Для сохранения JSON выполнен отдельный прямой instrumentation запуск, затем adb pull.
5. Попытка инструмента Studio обработать команду с локальным GGUF 639 MB вызвала Java heap space
   до запуска shell; перенос каталога данных целиком позволил выполнить ту же передачу через ADB.
   Это ошибка host IDE/tool, не Android OOM.

## Не проверено

Физический Redmi Note 9 Pro, native ARM inference, 15-минутный реальный разговор,
WER, DER, ошибка границ относительно эталона, устойчивость полного пайплайна, утечки памяти,
пользовательский сценарий авиарежима. Эталонные русские разговоры и физический телефон запрошены.

## Решение для следующей итерации

Речевые модели и Qwen подходят для дальнейшей интеграции по факту короткого CPU inference.
Порог для продукта остаётся предварительным и настраиваемым; не считать диаризацию точной.
Продолжить UI/Room/два источника аудио, затем объединить их с проверенными движками.
Финальную приёмку и 15-minute/ARM gates не объявлять пройденными.
