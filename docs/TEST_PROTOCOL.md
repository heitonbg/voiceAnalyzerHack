# Протокол проверки PrivateScribe

Нельзя заполнять метрики предположениями. Для каждого прогона хранить:
SHA входа, лицензию/согласие на запись, модель и SHA, runtime commit, ABI процесса,
SDK, physical/emulator, CPU threads, длительность, параметры VAD/кластеризации,
время загрузки, время inference, контрольную расшифровку/RTTM и сырые логи.

## Уровни доказательности

1. Сборка APK подтверждает только компиляцию/упаковку.
2. Android smoke на коротком WAV подтверждает запуск выбранных весов.
3. Сравнение с независимой разметкой даёт WER/DER и ошибку времени.
4. 15 минут непрерывного пайплайна на 4 GB с замерами памяти подтверждают устойчивость.
5. Полный пользовательский сценарий в авиарежиме подтверждает автономность интерфейса.

Не переносить результаты эмулятора на Redmi Note 9 Pro.
arm64-трансляция эмулятора не является испытанием физического ARM CPU.

## Матрица испытаний

| Сценарий | Данные / проверка |
|---|---|
| WAV / MP3 / M4A | SAF, реальный decoder, mono/stereo, 8/16/44.1/48 kHz |
| Ошибочные файлы | усечённый контейнер, нет аудиодорожки, повреждённый codec, пустой файл |
| Русская речь | чистая, шум, дальний микрофон, числа, имена, смешанный язык |
| 2 участника | смены коротких реплик, длинная пауза, возвращение голоса после нескольких блоков |
| 3+ участников | автоматический и заданный k, похожие тембры, ложное раздвоение голоса |
| Overlap | пересечения сохраняются; не обещать разделённый текст без separation |
| 15 минут | постоянный объём PCM-буферов, запись на диск, память, CPU, RTF |
| Диктофон | start/pause/resume/stop, отказ в разрешении, уход в фон, отключение микрофона |
| Сбой | process death, нехватка диска, missing/corrupt model, продолжение с checkpoint |

| Экспорт | точный набор ключей, integer ms, end > start, Unicode, escaping, overlaps |
| LLM | реальные выводы, ссылки существуют, отсутствие срока/ответственного, prompt injection |
| UI | light/dark, масштаб шрифта 200%, rotation, компактное/широкое окно, insets |
| Offline | отключённые Wi-Fi/mobile data, manifest без INTERNET, полный сценарий |

## Метрики

WER = (substitutions + deletions + insertions) / reference_words.
Нормализацию фиксировать до измерения: регистр, пунктуация, ё/е, числа.
Не сравнивать модели при разных нормализаторах или разных примерах.

DER: независимый RTTM, общий timeline, оптимальное глобальное соответствие speakers,
отдельно speech missed / false alarm / speaker confusion.
Зафиксировать collar (например 250 ms) и считать ли overlap; публиковать оба варианта при возможности.

Время: интервалы относительно исходника, median/p95 абсолютной ошибки начала/конца
по ручной разметке. Не называть VAD-границы точными word timestamps.

RTF = wall inference seconds / audio seconds; отдельно decode, diarization, ASR, LLM и total.
Отдельно cold/warm model load. Эмулятор не даёт реалистичную оценку Snapdragon.

Память: PSS/RSS native + Java, системный LMK/OOM, выборка во время работы.
Разовый Debug.getPss() не является пиковым значением.
Размер APK считать в bytes, размеры моделей отдельно, включая место после распаковки.

## Сценарий будущего видео

1. Показать устройство, отключить сеть, открыть список установленных моделей.
2. Импортировать новую реальную русскую запись с двумя/тремя участниками.
3. Показать этапы и уже сохранённые реплики без выдуманного ETA.
4. Дождаться финальной глобальной диаризации, проверить возвращение первого голоса.
5. Перейти к аудио по реплике; исправить speaker/text с сохранением оригинала.
6. Экспортировать JSON и показать точную схему.
7. Запустить реальную локальную LLM; проверить задачи/сроки и ссылки на реплики.
8. Сделать короткую запись с паузой и возобновлением, сохранить в историю.
9. Показать реальные измерения и ограничения.

Это сценарий приёмки после реализации. Он не утверждает, что эти функции уже работают.
